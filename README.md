# 币安监控系统 (GitHub Actions 版) - 部署指南

这是一个完全免费的云端部署方案。

## 1. 准备工作

### 获取 Firebase 密钥 (Service Account Key)
1. 访问 [Firebase 控制台](https://console.firebase.google.com/)。
2. 进入 **Project Settings (项目设置)** -> **Service accounts (服务账号)**。
3. 点击 **Generate new private key (生成新的私钥)**。
4. 你会下载到一个 `.json` 文件。**请妥善保管这个文件，不要发给任何人。**
5. 用记事本打开这个 JSON 文件，复制里面的**全部内容**。

## 2. GitHub 设置

1. **创建仓库**: 在 GitHub 上创建一个新的仓库 (Repository)，建议设为 **Private (私有)**。
2. **上传代码**: 将本目录 (`binance_monitor_gha`) 下的所有文件上传到该仓库。
   - 确保 `.github/workflows/monitor.yml` 路径正确。
3. **添加 Secrets**:
   - 进入仓库的 **Settings (设置)** -> **Secrets and variables** -> **Actions**。
   - 点击 **New repository secret**，添加以下三个变量：

| Name | Secret | 说明 |
| :--- | :--- | :--- |
| `TELEGRAM_BOT_TOKEN` | (你的 Bot Token) | 原配置中有 (`8577...`) |
| `TELEGRAM_CHAT_ID` | (你的频道 ID) | 原配置中有 (`-100...`) |
| `FIREBASE_CREDENTIALS` | (刚才复制的 JSON 内容) | **整段粘贴** |

## 3. 验证运行

1. 进入仓库的 **Actions** 标签页。
2. 你应该能看到 "Binance Monitor Task" 工作流。
3. 点击左侧的 "Binance Monitor Task"，然后点击右侧的 **Run workflow** 按钮进行手动测试。
4. 如果变成绿色 ✅，说明配置成功！之后它会自动每30分钟运行一次。

## 常见问题
- **找不到 Actions 标签页？** 确保 `.github/workflows/monitor.yml` 文件存在且在正确的位置。
- **报错 `firebase_admin.exceptions`?** 检查 `FIREBASE_CREDENTIALS` 是否复制完整，必须是合法的 JSON 格式。

## 4. 信号口径说明（2026-09-13 更新：低位闸门 + 窗口改造）

### 4.1 为什么改

原实现有两个方向性问题：

1. **完全不知道标的贵不贵。** 只看 OI 增幅和 2h 涨跌，经常把"已经涨过一大截"的币
   当成机会推出去。核查时发现被推得最多的 `HYPE` 处在一年区间的 **84%**、`ZEC` 在 **87%**，
   都在一年高位附近。
2. **把"价格上涨"当成好消息。** 原 `WarmupTracker` 用 `price_up` 作为"✅共振确认"加分。
   实际要的是相反的东西：**OI 在累积、价格没怎么动**才是「有人悄悄建仓」。

回测也印证了这点：回填 431 条信号结果后，
「持续升温」「OI爆增」两条规则（占全部信号的 81%）7 天超额**中位数分别是 −0.45% 和 −4.78%**，
胜率 42% / 37%。而「超跌反弹」中位数 **−5.23%**。

### 4.2 新增：一年低点分位（低位闸门）

```
pos = (现价 − 365日最低) / (365日最高 − 365日最低)      # 0=一年最低, 1=一年最高
dd  = (现价 − 一年最高) / 一年最高 × 100                # 距一年高点的回撤%
```
- `pos <= 0.25` → 记为 **🟢低位区**
- 数据源：币安日线 klines（**免 key**，与原有取数同源，零新增依赖）
- **只给候选币算**，不给全部 ~150 个币算，把请求量从 ~150 次降到 ~20 次

报告里每个候选后面会带 `位:12%🟢低位` 这样的标签；`位:?` 表示日线不足 60 根（次新币不判定）。

### 4.3 信号分栏（按优先级，越靠前越符合"买得便宜"）

| 分栏 | 含义 | 处置 |
|---|---|---|
| 🟢 **底部启动** | 一年分位 ≤25% + OI 累积 + \|涨跌\| ≤5% | **重点看** |
| 🟢 **OI 温和累积** | OI 累积 + 价格平静（\|涨跌\| ≤5%） | 看 |
| ⚪ **OI 增 · 价格微跌** | 需分多空：附 LS 判定（多头吸筹 / ⚠️空头加仓） | 看方向 |
| 🔴 **风险标记** | OI 增但价格已冲高（FOMO，右侧） | 有信息价值，不追 |
| 💎 **超跌区间** | 价格大幅下跌 | 仅供参考 —— 回测显示超跌不必然反弹 |

> ⚠️ 「OI 涨 + 价格跌」**不能直接当左侧机会**：可能是多头逢跌吸筹，也可能是空头在加仓。
> 这两者含义相反，所以对这类候选会额外取一次大户多空持仓比（`topLongShortPositionRatio`）
> 来定性，报告里写成 `多头吸筹(LS 1.24)` 或 `⚠️空头加仓(LS 0.83)`。

### 4.4 窗口与排序

- `WarmupTracker.MAX_DAYS`：**5 天 → 30 天**。"缓慢累积"是周级现象，5 天窗口量到的是噪音。
- 排序依据从「OI 涨幅」改为 **OI-平静比**：
  ```
  平静度    = 窗口内 (最高 − 最低) / 最低 × 100       # 越小越平
  OI-平静比 = OI 累计涨幅 ÷ max(平静度, 0.5)          # 越大越像悄悄建仓
  ```
  同样 OI 涨幅下，价格越平静排得越前；价格已经冲高的会被排到后面并标 🔴。
